- 版本：v0.2

## 2. 产品定位

本产品是一个基于 AR 的博主妆造试妆与分享平台，第一版按正常消费者 App 形态设计，首屏以相机试妆为核心，核心目标是先把类似完美彩妆的 AR 试妆效果做好。

美妆博主在平台上传自己的妆造模板，比如口红、眼影、腮红、高光、修容、妆容步骤和产品色号。用户打开 App 后，可以通过前置摄像头实时 AR 试妆，把博主的妆造叠加到自己脸上，判断这个妆适不适合自己。

如果用户喜欢这个妆造，可以进入博主详情页，查看教程、产品清单，并跳转到博主的小红书、抖音等账号看完整内容。用户也可以把 AR 试妆后的照片或视频保存下来，发布到小红书、抖音等平台，带上妆造来源或博主账号，形成二次传播。

核心闭环：

```text
博主上传妆造
-> 平台审核
-> 用户 AR 试妆
-> 用户保存/分享试妆效果
-> 用户跳转博主账号看教程
-> 博主获得流量和转化
```

这个产品不是单纯的 AR 试妆工具，而是一个“妆造内容传播平台”。

## 3. 用户角色

### 3.1 普通用户

想低成本尝试博主妆造、产品色号和妆容风格的人。

核心需求：

- 看某个博主妆造是否适合自己的脸。
- 快速试不同色号和妆容。
- 保存试妆照片或视频。
- 找到原博主、教程和产品清单。

### 3.2 美妆博主 / 创作者

希望自己的妆造更容易被用户试用、传播并导流的人。

核心需求：

- 上传或配置自己的妆造模板。
- 绑定品牌、产品和色号。
- 让用户在自己脸上试妆。
- 把用户流量导回小红书、抖音等平台。

### 3.3 平台 / 管理员

负责内容质量、审核、模板管理和产品数据维护的人。

核心需求：

- 审核图片、文案、产品信息和外链。
- 通过、拒绝或下架妆造模板。
- 控制盗图、假冒博主、虚假宣传、违规链接等风险。

## 4. 产品目标

### 4.1 MVP 目标

- 在 iPhone 12 及以上设备上做出可信的实时 AR 口红试妆效果。
- 第一版按全球发布思路设计，不限定中国市场。
- 第一版具备完整 App 闭环：权限、试妆、拍照、录视频、预览、保存、分享、错误提示。
- 建立可扩展的妆造模板结构，让产品从口红平滑升级到全妆。
- 支持用户切换妆造、调节浓度、前后对比、拍照和视频保存。
- 让数据结构能接上博主上传、产品清单、分享、水印和审核。

### 4.2 MVP 暂不做

- 完整公开的博主上传系统。
- 社区 feed 和推荐流。
- AI 自动从博主照片提取完整妆容。
- 完整 3D 材质引擎。
- 商业级审核后台。
- 支付、电商交易、联盟返佣。
- 公开测试版本默认不做登录；如果后续需要收藏、云端同步、创作者身份，再加账号体系。

这些能力需要提前设计兼容，但第一版不完整实现。

## 6. 产品功能架构

长期产品由 5 个核心模块组成：

```text
1. AR 试妆引擎
2. 妆造模板系统
3. 产品/色号系统
4. 博主/内容系统
5. 审核/发布系统
```

### 6.1 AR 试妆引擎

负责实时识别和渲染。

能力包括：

- 人脸追踪。
- 脸部分区 mask。
- 唇部、脸颊、眼皮、眉毛、鼻梁、高光、修容区域识别。
- 妆效图层渲染。
- 防抖和跟随优化。
- 光线适配。
- 拍照和视频保存。

MVP 范围：

- 只做口红。
- 保证唇部 mask 和口红渲染可信。
- 保留调试和性能工具。

### 6.2 妆造模板系统

这是整个产品的中枢。

一个妆造不要设计成“一个口红颜色”，而要设计成“很多妆效图层”：

```text
MakeupTemplate 妆造模板
-> products 产品
-> layers 妆效图层
   -> 口红层
   -> 腮红层
   -> 眼影层
   -> 高光层
   -> 修容层
```

每一层回答这些问题：

```text
画在哪里？
用什么产品/颜色？
多浓？
什么质感？
边缘多柔？
第几层渲染？
```

MVP 范围：

- 4 个内置妆造模板。
- 每个模板只有 1 个 lips 图层。
- 数据结构提前兼容腮红、眼影、高光、修容。

### 6.3 产品/色号系统

负责品牌和商品信息。

字段包括：

- 品牌。
- 产品名。
- 色号编号。
- 色号名称。
- 展示颜色。
- 教程或购买链接。
- 产品图，可选。

MVP 范围：

- 先用本地写死的产品/色号数据。
- 暂不做产品数据库后台。
- 公开测试阶段不使用真实品牌名、Logo、商品图和官方色号命名，先使用非品牌 demo 色号。

### 6.4 博主/内容系统

负责博主身份、妆造详情、教程链接和流量回流。

未来字段：

- 博主名称。
- 头像。
- 简介。
- 小红书链接。
- 抖音链接。
- 教程链接。
- 博主发布的妆造模板。

MVP 范围：

- 先预留数据字段。
- 暂不开放公开博主上传。

### 6.5 审核/发布系统

负责内容安全和模板状态流转。

博主上传的妆造模板需要有状态：

```text
draft 草稿
pendingReview 待审核
approved 审核通过
rejected 审核拒绝
archived 已下架/归档
```

审核对象：

- 妆造封面图。
- 教程图。
- 标题和描述。
- 产品信息和功效描述。
- 外部链接。
- 博主身份。
- 盗图/侵权风险。

MVP 范围：

- 先在模板结构里预留审核字段。
- 用户端只展示 approved 或内置模板。
- 上传和后台审核后置。

## 7. 代码架构

代码建议拆成 5 层：

```text
Domain / Data 数据层
AR / Tracking 识别层
Renderer 渲染层
UI 产品界面层
Storage / Platform 存储和平台层
```

### 7.1 Domain / Data 数据层

负责定义稳定的产品概念。

建议类型：

- `MakeupTemplate`
- `MakeupLayer`
- `MakeupProduct`
- `CreatorProfile`
- `CreatorLink`
- `ReviewStatus`
- `MakeupTarget`
- `MakeupMaterial`
- `MakeupBlendMode`

这一层不应该关心相机、模型、Core ML 或渲染细节。

### 7.2 AR / Tracking 识别层

负责找到脸部区域。

职责：

- 相机会话。
- 人脸 landmark。
- Core ML face parsing。
- 区域 mask。
- 跟踪平滑。

未来抽象：

```text
MakeupRegionProvider
```

它把语义区域映射成 mask：

```text
face.lips.full -> upper_lip + lower_lip mask
face.cheek.left -> 左脸颊 mask
eye.upper_lid.left -> 左眼皮 mask
```

以后换模型，只改这一层，不改模板结构。

### 7.3 Renderer 渲染层

负责把妆效图层画到脸上。

职责：

- 读取 `MakeupTemplate.layers`。
- 按 `order` 排序。
- 向 `MakeupRegionProvider` 请求每个 target 的 mask。
- 根据颜色、透明度、混合方式、质感、羽化、渐变、贴图渲染。

MVP：

- 只实现 `face.lips.full` 口红颜色层。

未来：

- 腮红 renderer。
- 眼影 renderer。
- 高光 renderer。
- 贴图/材质 renderer。
- 3D 人脸贴合 renderer。

### 7.4 UI 产品界面层

负责用户操作。

当前和近期 UI：

- 相机预览。
- 妆造/色号选择。
- 浓度滑杆。
- 前后对比。
- 调试按钮。
- 拍照按钮。

未来 UI：

- 妆造详情页。
- 产品清单。
- 博主主页。
- 教程跳转。
- 创作者上传/编辑入口。

### 7.5 Storage / Platform 存储和平台层

负责模板加载、保存和后续远程数据。

MVP：

- 本地模板 store。
- 内置 Swift fixture 或 JSON。

未来：

- 远程模板 API。
- 博主草稿 API。
- 审核状态 API。
- 产品色号数据库。
- 用户试妆历史。

## 10. MVP 详细功能需求

### 10.1 首次启动与权限

需求：

- 用户首次打开 App，进入权限引导或直接触发系统相机权限请求。
- 相机权限通过后，进入主相机试妆页。
- 用户拒绝相机权限时，显示明确提示，并提供跳转系统设置的入口。
- 保存照片或视频时，请求相册写入权限。
- 用户拒绝相册权限时，仍可继续试妆，但保存时提示开启权限。

不做：

- 第一版不要求登录。
- 第一版不上传用户人脸图像。
- 第一版不做云端同步。

### 10.2 实时 AR 试妆

需求：

- App 打开后默认使用前置相机。
- 自动识别人脸和嘴唇。
- 默认加载一个 demo 口红妆造模板。
- 口红效果实时贴合用户嘴唇。
- 支持正脸、轻微转头、轻微低头/抬头、张嘴、嘟嘴、轻微表情变化。
- 无人脸或识别不稳定时，给出轻量状态提示，不打断相机。

### 10.3 妆造模板切换

需求：

- 底部展示 4 个 demo 妆造模板。
- 每个模板展示短名称和颜色 swatch。
- 点击模板后实时切换妆效。
- 当前选中模板有明确选中态。
- 模板数据使用 `MakeupTemplate + MakeupLayer`，即使 MVP 只渲染口红层。

公开测试策略：

- 使用 demo 命名。
- 不展示真实品牌名、Logo、官方商品图和官方色号命名。

### 10.4 浓度调节

需求：

- 支持 0% 到 100% 调节。
- 拖动时妆效实时变化。
- 默认浓度由模板提供。
- 重置按钮恢复默认模板和默认浓度。

### 10.5 前后对比

需求：

- 提供一键隐藏/显示妆效按钮。
- 隐藏妆效时，相机、人脸识别和 mask 推理继续运行。
- 再次显示时，妆效应立即恢复到当前模板和浓度。

### 10.6 拍照

需求：

- 点击拍照按钮后，生成包含 AR 妆效的图片。
- 拍照时提供轻反馈，例如闪屏或震动。
- 拍照后进入预览页。
- 预览页支持保存到相册、系统分享、返回重拍。
- 保存失败时显示失败原因。

### 10.7 视频录制

需求：

- 支持切换到视频模式或长按录制。
- 开始录制后显示录制计时。
- 录制过程中保留实时 AR 妆效。
- 再次点击停止录制。
- 录制结束后进入预览页。
- 预览页支持保存到相册、系统分享、返回重拍。

### 10.8 调试模式

需求：

- 开发期保留调试入口。
- 调试模式显示嘴唇定位线。
- 调试模式显示 FPS、Core ML 耗时、mask 延迟。
- 公开测试包可以隐藏调试入口，或通过内部方式开启。

### 10.9 MVP 明确不做

- 不做登录。
- 不做社区 feed。
- 不做博主公开上传。
- 不做真实品牌公开展示。
- 不做购买、支付、电商交易。
- 不做复杂个人主页。

## 11. 页面结构和交互流程

### 11.1 页面结构

MVP 页面：

```text
1. 启动/权限页
2. 相机试妆页
3. 妆造选择面板
4. 妆造详情弹层
5. 拍照/视频预览页
6. 设置/权限说明页
7. 错误状态页
8. 开发调试 HUD
```

### 11.2 相机试妆页

页面定位：

- App 主页面。
- 打开 App 后的核心体验。

页面元素：

- 前置相机实时预览。
- 顶部状态区：识别状态、当前妆造名称。
- 顶部操作区：前后对比、调试入口、设置入口。
- 底部拍摄区：拍照按钮、视频模式入口。
- 底部妆造区：模板 swatch、名称、浓度调节。

交互：

- 左右滑动或点击切换模板。
- 拖动滑杆调整浓度。
- 点击眼睛按钮切换前后对比。
- 点击拍照生成图片。
- 切换视频模式后点击录制。

### 11.3 妆造选择面板

页面定位：

- 用户快速选择 demo 妆造。

展示内容：

- 模板短名称。
- 颜色 swatch。
- 当前选中态。
- 默认浓度。
- 质感标签，例如柔雾、哑光、水光。

交互：

- 点击即实时切换。
- 可进入妆造详情弹层。

### 11.4 妆造详情弹层

页面定位：

- 让用户知道当前试的是什么妆。

MVP 展示：

- 妆造名称。
- demo 色号名称。
- 质感。
- 默认浓度。
- 图层说明：当前只显示口红层。

后续展示：

- 产品清单。
- 博主来源。
- 教程链接。
- 审核状态只对创作者/管理员可见。

### 11.5 拍照/视频预览页

页面定位：

- 用户确认拍摄结果并决定保存或分享。

展示内容：

- 拍摄结果。
- 当前妆造名称。
- 保存按钮。
- 系统分享按钮。
- 重拍按钮。

交互：

- 保存成功后提示“已保存到相册”。
- 分享调用系统分享面板。

### 11.6 设置/权限说明页

MVP 内容：

- 相机权限说明。
- 相册权限说明。
- 隐私说明：第一版本地处理，不上传用户人脸图像。
- App 版本信息。

### 11.7 核心用户流程

```text
打开 App
```

## 14. 技术风险

### 14.1 Mask 精度

风险：

- 唇线不贴。
- 嘴角覆盖不足。
- 张嘴、嘟嘴、转头时跟不上。

应对：

- 继续训练自研轻量 face parsing 模型。
- 重点看 upper_lip、lower_lip、inner_mouth 指标。
- 用 iPhone 12 真机测试。

### 14.2 妆效真实感

风险：

- 看起来像贴纸。

应对：

- 保留皮肤/唇纹纹理。
- 使用混合模式、透明度、羽化。
- 预留材质、渐变、贴图参数。
- 后续接 3D 人脸贴合。

### 14.3 性能

风险：

- Core ML 推理或渲染导致相机卡顿。

应对：

- 推理放后台线程。
- 缓存最近 mask。
- 用 HUD 观察 FPS、ML 耗时、mask 延迟。
- 调整推理间隔和输入尺寸。

### 14.4 内容合规

风险：

- 盗图。
- 假冒博主。
- 虚假产品功效。
- 违规链接。
- 品牌侵权。
- 未获授权使用真实品牌名、Logo、商品图、官方素材或官方色号宣传，可能带来商标、版权、平台审核或商业合作风险。

应对：

- 早期只做内置 demo 模板。
- 公开测试阶段不使用真实品牌素材和真实品牌命名；内部开发可把真实色号作为颜色参考，但不作为公开展示内容。
- 模板结构预留审核状态。
- 上传后先人工审核，早期人工审核由产品负责人完成。
- 外链白名单。
